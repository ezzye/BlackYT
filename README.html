BlackYT

A small Android PWA for selected public YouTube audio. In phone mode, Termux fetches audio directly from YouTube and passes it locally to Chrome on the same Pixel. No Mac or cloud server carries the audio. The earlier Mac prototype keeps its direct-browser streaming mode.

Run it

The environment is prepared on this Mac. From the repository folder:

./start.sh
# Open http://localhost:8765

Fresh setup requires Python 3.10+ and Deno or a supported Node runtime:

./setup.sh
./start.sh

For the current Wi-Fi phone test:

./start.sh --listen 0.0.0.0 --allow-host 192.168.1.228

The existing phone certificate is retained locally for private HTTPS:

./start.sh --listen 0.0.0.0 --port 8766 --allow-host 192.168.1.228 --cert .tls/server-cert.pem --key .tls/server-key.pem

Implemented

  • Music-category verification before playback and title/channel include/exclude filters.
  • Audio queue, next/previous, seeking and Media Session controls.
  • Installable PWA shell with offline interface; search and streams remain online.
  • Only HTTPS YouTube media hosts are accepted. Phone mode exposes an opaque audio route on phone loopback only; Mac mode has no media relay.

The owner reported two-minute screen-off playback in Android Chrome, warning-free private HTTPS, successful Pixel 10 Pro XL installation and playback from the installed app. Queue changes while locked and headset outcomes were not separately confirmed.

Prototype limits

In Mac-assisted mode, the Mac helper must remain reachable and share the phone’s internet exit. Phone mode runs entirely in Termux and Chrome on the Pixel. YouTube changes can interrupt this unofficial access route. Creator promotions inside a recording are not removed. The current local server certificate expires on 22 October 2026; a different LAN address needs a new certificate setup.

This repository is local. Publishing or deploying it is a separate action.

Phone-only version with Termux

The owner chose to run the resolver on a Pixel 10 Pro XL. The phone package uses Python, Node and pinned yt-dlp + EJS dependencies inside Termux. Both resolution and Google media requests leave through the phone connection. Termux streams audio to the browser locally on the same Pixel, avoiding the direct-browser request that returned403 for Prince. The phone listener binds only to127.0.0.1; no cloud hosting or off-device media relay is used. The Mac prototype retains its original direct-browser mode.

Open the standalone phone setup guide. On the phone during initial transfer: Wi-Fi setup guide. After installation, open http://127.0.0.1:8765/ on the Pixel and install the separate BlackYT Phone icon. Keep the foreground Termux session running; launch with blackyt.

Rebuild download artifacts with .venv/bin/python phone/build_phone.py --transfer-url http://192.168.1.228:8765. Bundles include only the whitelisted runtime, exclude local certificates and private files, and are pinned by SHA-256 in the installer and setup command. Generated downloads are ignored by Git. Existing earlier download artifacts are retained for commands already copied by the owner.

The updated phone route played Prince’s When Doves Cry on the physical Pixel: local HTTP 206, audio/mp4, playback time advancing, and owner confirmation “It works!”. The owner also confirmed the manual queue works after correcting which button was tapped. Exact two-minute locked playback and a locked queue transition on mobile data were not separately confirmed. Earlier screen-off and installation passes apply to the Mac-assisted version. Android may stop Termux, so background battery allowance and a real Pixel test matter.
