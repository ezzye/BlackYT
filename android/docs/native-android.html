BlackYT · Native Android

Find your next favourite.

BlackYT is a single Android app for finding and playing YouTube music links. Stream extraction and audio playback happen on the phone.

v0.3.0-native · Private Android preview

Release

The private native preview is v0.3.0-native, with BlackYT-Android-v0.3.0.apk (about 5.5 MB). The APK and this offline guide are available as private release assets.

Validation so far

The signed native release builds and is installed on the Pixel 10 Pro XL; its installed APK hash matches the release file. Five unit checks pass, and release lint reports zero errors with routine warnings. Direct native Googlevideo audio returned HTTP 200. The owner confirmed audible native playback, continued playback with the screen locked, and automatic playback of the next queued song while locked. Those owner checks used the pre-release build; the final signed release has the same playback engine. The owner then confirmed that the final signed release plays a newly searched song on mobile data with USB unplugged and continues with the screen locked. The Mac and Termux are not playback dependencies.

Install the APK

  1. On your Android phone, sign in to GitHub with an account authorized for the private BlackYT repository.
  2. Open the v0.3.0-native release page, and download BlackYT-Android-v0.3.0.apk.
  3. Open the downloaded APK. If Android asks, allow the browser or file manager to install apps, return to the installer, and tap Install.
  4. Open BlackYT from your launcher. The previous Chrome home-screen app called BlackYT Phone belongs to the older Termux setup.

Normal playback needs no Termux, Chrome, local server, Mac, account, or cloud relay.

Search and play

  1. Tap the search box. Enter a song or artist, or paste a YouTube link, then tap Search. There is no external Open or Share link action; paste the link into the search box.
  2. Music results only is checked initially. Uncheck it if a result you want is missing. Music classification depends on available YouTube metadata and is not guaranteed.
  3. Optionally enter comma-separated words in Include any words or Exclude any words. Include keeps a result when any included word appears. Exclude removes it when any excluded word appears. Matching uses the available title and channel text.
  4. Tap Play on a result to start it now, or Add to append it to the FIFO queue.
  5. Use Previous, Stop, Play/Pause, Next, and the seek bar in the player. Android notification and lock-screen controls use the native player session.

The queue lasts only for the current app session. Filter settings persist. There are no offline downloads and no sign-in.

If a song stops

Check that the phone is online and tap Retry current song. Retry obtains a fresh stream URL, which may help after a network change or when an earlier link expires. Some videos, including age-restricted or otherwise restricted items, may not be available.

Playback path

The phone requests YouTube data and streams audio directly from YouTube's Googlevideo host. BlackYT does not route audio through a cloud relay or request the YouTube player's separate ads. Promotions embedded in a recording remain part of that recording. YouTube may change its service and break search or playback.

Device checks and current limits

The owner confirmed native audio and automatic queue continuation with the screen locked. The final release is installed. The owner also confirmed a newly selected song plays on mobile data with USB unplugged and continues with the screen locked. Queue contents currently last only for the running app session; filters persist. YouTube service changes may require an app update.

Build and signing

Source is GPL-3.0-or-later; see LICENSE and NOTICE. Build uses Java 17, Android SDK 36, Build Tools 35, Android Gradle Plugin 8.13.2, and Gradle 8.13.

From the Android source folder: ./gradlew assembleDebug, ./gradlew testDebugUnitTest, and ./gradlew lintRelease. Local release signing reads ../.local/android-signing.properties. Keep the signing properties and keystore private; updates must use the same key. Keep a protected backup in secure credential storage and a second encrypted, access-controlled location. Never place key material in a release, HTML file, or Git.
