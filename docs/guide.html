What is ready

The owner confirmed audible Prince playback, a working manual queue, and two minutes of playback with the screen locked on the Pixel 10 Pro XL. The backend passed 22 checks. The installer has checks for altered files, unsafe archive paths, local-file installation, and safe reruns.

The portable release ZIP is a new installation route. Its package and mocked installer checks are verified; a fresh physical-phone installation from this exact ZIP has not been repeated. A queue transition while locked and every Android battery policy are not certified.

Install without a Mac

You need Android, Chrome, internet access, and Termux. This private release is available only to your GitHub account and people you grant access to. No GitHub password or access token needs to be stored in Termux.

  1. Install Termux from the official F-Droid page, then open it. If you already have Termux, keep the same distribution; different sources have different signing keys.
  2. In Chrome, sign in to GitHub and open the v0.2.0 release. Under Assets, download BlackYT-Phone-v0.2.0.zip. Use that exact filename in Downloads. If Android adds “(1)” to it, rename the new file to the stated name before continuing. Do not choose GitHub’s generic “Source code” ZIP for this route.
  3. In Termux, paste this preparation command and press Enter. Let it finish; it updates Termux packages together before installing tools.
apt update && apt full-upgrade -y && apt install -y python curl unzip termux-tools

Next run this command and allow the Android storage prompt. It gives Termux access to shared files, including Downloads. This is needed for this local ZIP transfer; BlackYT itself keeps its runtime in Termux private storage.

termux-setup-storage

After granting permission, paste the installation command:

mkdir -p "$HOME/blackyt-setup-v0.2.0" && unzip -o "$HOME/storage/downloads/BlackYT-Phone-v0.2.0.zip" -d "$HOME/blackyt-setup-v0.2.0" && bash "$HOME/blackyt-setup-v0.2.0/setup-phone.sh"

The setup checks the bundled installer fingerprint; that installer checks the app archive before installing it. Download from the trusted private repository over HTTPS. These checks are not an independent digital signature.

Wait for Python/Node and the pinned resolver dependencies to install. Chrome should open http://127.0.0.1:8765/. Look for Running on this phone. Chrome’s ⋮ menu → Add to Home screen → Install, if offered, creates the separate BlackYT Phone icon. This loopback address needs no custom certificate.

Daily use and updates

Open Termux, type blackyt, and press Enter. Keep its session running while listening, then use BlackYT Phone. After a restart or if Android stops Termux, run blackyt again. Allow Termux background activity or unrestricted battery use where your Android version offers it.

blackyt

Play starts a search result immediately. Add puts it in the manual queue. The next queued track starts when the current one ends. BlackYT does not choose more songs automatically. Music mode checks YouTube’s Music category before playing; interest filters match title/channel words and are best effort.

To stop: return to Termux and press Ctrl+C. To update: stop the current session, download the new release, and follow that release’s matching guide. Do not mix an installer and archive from different releases. Chrome may need one reload after updating its app shell.

Preferences stay in that browser’s local storage; the queue is only in the current page session. Note important filter settings before clearing Chrome data. There is no persistent playlist or offline audio library.

The browser’s direct request for Prince was refused with HTTP 403. A native Termux HTTPS request succeeded. The phone version therefore fetches YouTube media in Termux and forwards it over loopback to the browser on the same phone. There is no external audio relay or cloud bandwidth bill. Mobile data and battery use still apply.

The helper listens only on loopback in phone mode. It accepts short-lived opaque audio tokens and checks that media and redirect hosts remain HTTPS Googlevideo hosts. The service worker caches the interface, not tracks or API replies. It does not use YouTube account cookies. This unofficial route may change or be blocked; creator promotions already inside a recording remain part of that audio.

Making it one Android app

Recommended next stage: retain the search/filter interface where useful, but put playback in an Android service inside a signed APK. This is proposed work, not an APK included in this release.

RouteWhat the user installsAssessment
Current releaseTermux + Chrome PWAWorking baseline. Start Termux before listening.
One launcher iconA small launcher plus Termux and ChromeCan start a controlled Termux command, but still depends on two apps and permission setup.
True single APKOne BlackYT Android appOwn resolver, native playback service, queue, notification and updates. Recommended development target.

Android documents Media3 MediaSessionService for playback outside the app’s visible screen. The existing HTML interface could be bundled through WebViewAssetLoader, or rebuilt in native Android UI. The extraction layer would need a maintained native implementation such as NewPipeExtractor, or a separately tested embedded Python/JavaScript runtime.

A Trusted Web Activity uses the browser to display web content. It does not package the Termux helper by itself. A Termux command launcher can reduce taps but requires explicit external-command permission. Termux is GPLv3, and NewPipeExtractor has its own GPL terms; decide the native project’s licence before incorporating upstream code.

  1. Prove extraction and playback for the same test tracks in a native service.
  2. Move filters, queue and media controls behind that service; add audio focus and interruption handling.
  3. Test locked-screen playback, locked queue changes, network changes and Android restarts on the Pixel.
  4. Ship a signed APK with reproducible build instructions, source notices and an update path.
